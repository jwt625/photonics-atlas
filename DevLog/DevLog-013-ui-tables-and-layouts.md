# DevLog-013: UI: real loading, per-class component tables, column filters, accurate layouts

## Request (2026-11-04, Wentao)

1. Some of the loading animation is bullshit. Start showing the rows loaded asap, no filler shapes.
2. Component tab: different components get different table columns, not one table with a row per spec / parameter.
3. Table columns: discrete types filter by multi-select; other columns likewise, numeric ones by a number range.
4. Layout tab is horrible. Make physically and topologically accurate layouts after inspecting micrographs etc.

## Decisions

| id | decision | reason |
|---|---|---|
| D500 | No skeleton or placeholder shapes anywhere. `Skeleton.svelte` is deleted. Pages render their real frame (tree, table header, filter row) at once; rows come from a small head of real rows inlined in every page through `summary.json`, then part by part. The only loading indicator is a real count: "1240 / 3019 loaded" | request 1; a head in `summary.json` needs no extra round trip on tab change, unlike a page `load` |
| D501 | Tab change: active tab immediately, old page stays (dimmed) until the new one mounts; no overlay | request 1 |
| D502 | `/components` is one row per component. Family or subtype picked in the tree sets the columns: common columns (component, subtype, platform, core, fab, year, publication) plus one column per registry parameter reported in that selection, performance before geometry, by coverage; rarely reported columns start hidden behind a column chooser. "All classes" shows common columns and a class column only | request 2 |
| D503 | A cell with several rows of one parameter shows one representative (measured first, then no condition, no qualifier, metric order), a `+n` marker and all rows with conditions on hover. A cell keeps its basis badge. Row-level filters in the bar (basis, scope, wavelength range) restrict which rows feed the cells; the full list stays in the detail panel | a component has up to dozens of rows per parameter; insertion loss per coupler and fiber to fiber must not read as one quantity |
| D503a | (audit) Supersedes the scope bar filter of D503: a parameter with more than one scope in the selection gets one column per scope; no-scope and `unspecified` rows share a column; a single named scope keeps a plain label with the scope in the tooltip. `std` rows never enter a cell or a column, only the detail Values table. A stored bound is open at its value and matches on overlap: "> 60" fails max 60, passes min 100; "< 2" passes 0-1 | the audit found 447 fiber-chip representatives mixing 7 scopes, unlabelled, ranked as one quantity |
| D504 | One reusable table (`app/src/lib/table/`) on every table page: multi-select with counts for discrete columns, min / max range for numeric columns, contains for free text. Numeric range matches a cell if any row in it falls in the range; an active range excludes empty cells | request 3, applied everywhere it applies |
| D505 | Curated layouts supersede the parametric template drawing for the components that have one: per-component cell scripts (`scripts/layouts/cells/`) on a small geometry library compute polygons in micrometres after the paper's micrographs, SEMs, schematics and text have been read; output `app/static/data/layouts.json`. Components without a curated cell keep the template scene | request 4; a template cannot express focusing gratings, real AWG arrays, multi-pass heaters, contacts, undercuts |
| D506 | Supersedes D104 / D106 for drawings only: topology and proportions may be taken from a source figure, and dimensions may be read off a figure's scale bar. Such a reading never enters the metric table. It carries its figure locator and an uncertainty in the shape tip and is badged F. D104's no-invented-number rule stays: every shape states its source (metric row, stated text, figure reading, or assumed; assumed is dashed) | request 4; the metric table keeps its rules |
| D507 | No figure, image or pixel trace is copied into the repo or the site. Cells are new vector drawings computed from dimensions and read topology. Source figures stay local (gitignored) | rights are source-specific (`redistribution: restricted_local_only`) |
| D509 | Template fallback, after "i still see a bullshit AWG" (2026-11-04). The cartoon AWG generator is gone: an uncurated AWG shows a true-scale star coupler when FPR length and arm count are reported, arm stubs cut, array routing not drawn; otherwise nothing. Any template view with no reported dimension (D225 "schematic") is not shown: the page says not drawn, with the reason on hover | a drawing with no dimension from the source is not a drawing of that device |
| D510 | Curated views whose layout the source does not fix are not published, listed one by one in `scripts/layouts/build.py` `NOT_DRAWN` with the reason shown on the page. Th2A.9's 52 arms, star radius and delta L were all drafting guesses; dashed is not enough for a whole drawing. Assumed parts stay dashed inside a drawing the source does fix. Figures would lift these | same reason as D509 |
| D508 | Viewer: true scale always, wheel zoom and drag pan, per-layer visibility, no anamorphic stretch. Multi-scale structures are read by zooming, with detail views at stated scale where useful | a stretched axis is not a layout |
