   subtractions; su2026 prints dB/facet and says net single facet, cheben2015 never writes the halving. Recommendation: keep (rule 6 and its pitfall,
   gradkowski2023 and merged edge rows; D167 covers values whose arithmetic is not shown). Consequence: these rows, including 0.32 dB and the sub-1 dB
   SMF-28 cantilevers, do not rank under the `edge_taper` primary (`per_facet`). A primary that also accepts `loopback_half` would be a template change,
   not a batch change.
2. brusberg2025 evanescent m1-m14 stay `measured` + method `unspecified`. The rows exclude the FAU-to-IOX term, whose value and origin are not given for
   this measurement, so D428 (sun2025) would point to `author_estimate` + `loss_breakdown`. Recommendation: keep `measured`: the caption says measured,
   no subtracted number is printed, D167 and the lit_41 reading apply; sun2025 printed an approximate subtracted term. The same reasoning covers du2022
   pic_connector m1-m7 (input through GC and MMI, calibration not stated, paper says measured from a waveguide). To reverse, add `basis` and `method`
   ops on those rows.
3. du2022 printed values kept against the paper's own data (D417): better than 85 % against Table 1 and the 83 % Fig. 10 port 7 peak; +/-35 um against
   Fig. 10, where +/-35 um costs only about 0.3 dB by eye; 160 um against 80 um diameter; less than 1 dB against 1.11 dB (not entered). Recommendation: accept, all
   flagged in notes; a figure-read tolerance would replace a printed value with a reading.

   summary repeats it as demonstrated. Recommendation: accept. The Fig. 4 hardware is this paper's, but no value is tied to it apart from that sentence.
5. sutherland2019 scope `per_interface` (6 ops). Rule 6 labels the value chip-chip, while merged connector rows already use it. Recommendation: accept. To
   reverse, drop the six ops.
