## Coordinator questions

1. yang2024a fab "Applied Nanotechnology (ANT)" -> `org_applied_nanotools` (asked). The printed name is not the registry name ("Applied
   Nanotools Inc.") and `org_aliases.csv` has no Applied Nanotools alias; the supply review (lit_05, D564) held the same string for the org
   round. What ties it to Applied Nanotools: the printed abbreviation ANT, the stated flow (EBL, single-step ICP etch, PECVD SiO2 cladding on
   220 nm SOI with 2 um BOX, p.4 / p.6) and a merged precedent row (cmp_ofc2026_th1g2_trimodal_mzi_mss, printed "Applied Nanotool (ANT)
   foundry", mapped to the same org); no other registry org carries a similar name. The link from "ANT" to Applied Nanotools is outside
   knowledge, not text, so this is a variant mapping rather than an exact name. Recommendation: keep `org_applied_nanotools` on the four
   fabricated yang2024a rows (no op) and add "Applied Nanotechnology (ANT)" as an alias in the org round, which also resolves the held supply
   line to the same org. Strict alternative (Contract v7 "never a guessed mapping"): set `fab_org_ids` '' on te0_te1_unidir_mc, te1_hompf,
   te1_hompf_x2 and euler_bend now and restore it in a fix batch once the alias exists.
2. li2024b fab (asked). p.2 and p.8 use first person ("We fabricated" the 1 x 9 AWG; a second AWG "on the same chip"), all authors at Beijing
   Information Science & Technology University (`org_beijing_information_science_and_technology_university` exists), but the only process
   sentence (p.7) is passive and attributes the chip to "a 180 nm production line" with DUV lithography, implants and selective Ge epitaxy,
   which names a node / line without an operator. The first-person sentences are design-and-test summaries; none describes a process step the
   authors ran. Recommendation: keep fab empty with `process_name` "180 nm production line" (D536 printed node wording; gentry2015 named process
   without a named foundry), so the benchmark does not file this chip under the university as a foundry. Alternative: the university under
   rule 12 / D72 on the four li2024b rows.
3. li2024b AWG-to-PD taper as its own `waveguide_platform.transition` row (asked). The paper defines the 2.4 dB as the coupling loss between the
   AWG and the PD (Eq. (2), p.9-10), i.e. the Si-to-Ge inter-material coupling, and characterizes the taper separately (Fig. 5-6, > 95 % simulated,
   50 um). Rule 10 (on-chip inter-material transition) fits; the PD row has no parameter that would hold a coupling loss into its absorber,
   and merged III-V-on-Si taper rows (kurczveil2013) use the same class. Recommendation: keep; basis `author_estimate` / method loss_breakdown
   stays (subtracted terms not printed).
4. ni2024 per-crossing losses (asked). Patched to `measured` (4 rows). D80a makes explicit cascade / N arithmetic `derived` whether the authors
   or the batch did it, but here nothing is shown: the paper says ten crossings were cascaded to obtain average ILs, prints only the per-crossing
   values, and Fig. 9 already plots per-crossing transmission. That is the D167 / D452 case ("stated directly without shown arithmetic", "no
   total is printed and no arithmetic is shown"), and the merged ni2025a rows (same group, same reference-structure method) are `measured` by the
   lit_11 audit ruling. Recommendation: accept the patch, no ni2025a sweep. Alternative: keep `derived` (drop the four ni2024 metric ops) and
   sweep ni2025a to `derived` for consistency.
5. yang2024a mode-pass filters as `mode_converter.other` (asked). Confirmed: merged mode filters zhang2022a (TE1-pass), dagostino2015, li2021 and
   song2021b use the same class with `extinction_db` for the rejected mode. Recommendation: keep; a `mode_converter.mode_filter` subtype is a
   registry-extension candidate (five papers now), to be added with a reclassification sweep rather than per batch.
