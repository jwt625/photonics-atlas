## Coordinator questions

1. kita2021 no-heat-sink time constants (patched): the p.4 text gives t_fall 3.28 / t_rise 1.30 us, Table I gives Rise 3.28 /
   Fall 1.30 us. The distiller followed the text. The Fig. 8 traces (the measurement) show the light falling to 30 % in about
   1.35 us and rising to 70 % in about 3.3 us, so the table is right and the text is reversed. Recommendation: accept the patch
   (t_fall 1.30, t_rise 3.28, D417 note). D159 does not apply (one device, the figure resolves the conflict). The BATCH_REPORT
   judgment call is reversed accordingly.
2. zheng2020 endurance 500 vs 1,000 cycles: p.3 states "more than 1,000 times (500 cycles)" and p.10 "> 1,000 transitions"; the
   Fig. 3(e) / 4(d) axes are labelled "Number of Set/Reset cycles" to 1,000, which cannot be resolved from the render (points too
   dense to count). Recommendation: keep 500, qualifier `gt` (the paper's own explicit equivalence; registry definition "cycles
   ... as stated"; adya2024 / chen2022c precedent of entering cycles, not switching events), with the axis label in notes as
   entered. The per-length values out under D250: agree (D250 rejected per-length phase-shifter loss / extinction; nothing else in
   this paper is a per-device value that was left out).
3. gao2022 Q_i / Q_e `author_estimate` and empty fab: recommendation keep both. D403: the fit yields kappa and kappa_e but the
   paper does not say how the coupling branch was determined (D418 strict precedent). Fab: "L.W. provided the SiO2 samples" (and
   likewise for Si3N4 / AlGaAs / Ta2O5) plus passive Methods verbs is not a fabrication statement (D80b; white2024 lit_07
   precedent, "provided the laser chip"); the provider orgs are recoverable only from affiliations, which Contract v7 forbids
   (never fill fab from affiliation alone). If the coordinator wants a "provided the samples" rule, it should be a recorded
   decision applied corpus-wide, not a one-off here.
4. kita2021 fab / `process_name` empty: recommendation keep. "fabricated using a CMOS foundry" (p.4) and "a standard Si
   photonics foundry" (p.6) name no foundry, node or flow (Contract v7: never a generic word). For the benchmark, the rows would
   need a `family_override` in `config/benchmark.yaml` if they should appear in a foundry column; no affiliation-foundry rule
   applies (Waseda / NICT).
