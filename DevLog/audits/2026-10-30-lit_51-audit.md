## Rulings on the distiller's questions (evidence-based recommendations)

1. lira2012 isolation_db 3 dB: accept. p.4 Fig. 4 render: y-axis "Isolation (backward signal divided by forward
   signal)", linear, the 25.0 dBm trace dips to about 0.5 (3 dB) at 1558 nm; p.2 the quantity is the transmission
   between two single-mode waveguides; p.3 the MMIs radiate the converted odd mode, so the single-mode ports carry only
   the input frequency and the structure is a 2 x 2 scattering matrix with direction-dependent transmission. This is a
   port-to-port transmission isolation at the carrier, the registry's isolation magnitude. sohn2018 (lit_33) and
   kittlaus2020a (lit_45, D419) were sideband-efficiency contrasts with the carrier passing both ways; they do not
   apply. IL ~70 dB: keep `measured`, scope unspecified. p.4 "For this specific device, the insertion loss is around
   70 dB" is a device-level value of the measured device, stated directly (D167), not a loss-budget term or setup
   fact (nader2025 / D418 concerned parenthetical coupling figures); method and reference plane are not stated, so
   scope stays unspecified with the note. Alternative if the coordinator applies "origin not stated" strictly:
   author_estimate.
2. Frequency_converter rows in %: keep. The registry `power_conversion_efficiency_pct` is "optical power conversion
   efficiency as defined by the paper ... definition and reference plane in condition", and the header convention keeps
   linear efficiencies in % parameters. Merged precedents store signal-to-idler conversion gains above 100 %: ye2021
   339 %, umeki2010 631 % / 251 %, minami2023 691.8-1258.9 %, abe2025 1000 % / 1995 %. riemensberger2022 (lit_07) left
   its idler efficiency out because it had only an amplifier row ("no amplifier parameter"); it predates the D396
   frequency_converter-row practice and is not a contrary ruling. 1.698e6 % and 1e7 % are faithful conversions with the
   printed dB in notes. Optional registry follow-up only if 6-7 digit % values are unwanted in the app: a dB-form
   `conversion_gain_db` for frequency_converter.
3. bi2011 1.6 GHz: not entered, confirmed. GHz -> nm would be a domain conversion the registry avoids for widths
   (lit_14 otterstrom2019, lit_33 sohn2018 precedents). With otterstrom2019 2.5 MHz (lit_14 proposal
   `isolation_bw_mhz`) this is the second confirmed value: recommend one frequency-unit parameter (e.g.
   `isolation_bw_ghz`, level in condition) and entering 1.6 GHz at the 10 dB level, 1542 nm, TM (p.2). IL 18.8 dB
   on_chip_excess: endorsed (bi2011 section above).
4. Basis / scope / orgs: all endorsed. kuyken2011 on-chip gains derived (D166; p.2 definition plus the cutback coupling
   trace of Fig. 3(b)); keyvaninia2012 13 dB derived (reference-waveguide extraction, p.2); keyvaninia2012 3 um design
   gain read off Fig. 4: endorsed, value corrected to 8.1 dB; shoji2008 37 dB `device_total` not halved: endorsed (two
   facets, propagation subtracted, per-facet split not stated; fard2021 precedent; halving would need an equal-facet
   statement as nauriyal2019 had); foster2006 / kuyken2011 cross-sections not split (ye2021 ruling); fab bi2011 org_mit
   (author contributions, D395) and lira2012 Cornell + CNF (D83c) endorsed.
