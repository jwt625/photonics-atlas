## Coordinator questions (recommendations)

1. wang2014a "< 3 dB" IL for AWGs #2 / #3 (p.5 Sec. 2). Recommendation: drop both rows (patched). The sentence is one bound for
   two devices with no channel or statistic. For AWG #2 the paper's own extraction (Fig. 2(d)) puts all eight channels above
   3 dB (best about 3.13 dB), so the bound belongs to no measured channel of that device, and an `lt 3` row would rank it below
   its real best; for AWG #3 it adds nothing to the printed best 2.32 dB and the 2.32-4.7 dB range. D417 (tossoun2024) kept a
   printed value whose owner was clear and which the paper used in its own arithmetic; here the referent is the open point
   (D159 analogue, as D513 kittlaus2018 "< 1 dB"). The companion "< -17 dB" crosstalk rows agree with every channel of Fig. 2(e)
   and stay. Alternative: keep both as printed with the conflict notes (D417 letter); then remove the delete block and the two
   component-note ops.
2. "IL ranges from 2 dB to 4 dB" for each input (p.6). Recommendation: keep in notes only, as the distiller did. Fig. 4 shows
   points at 5-7 dB for both AWGs, and the sentence names no input / output set.
3. wang2014a fab and process. Recommendation: fab empty and `process_name` "130 nm CMOS process (200-mm SOI, 248-nm DUV)" kept.
   "The devices were fabricated with a 130 nm CMOS process" (p.3) is passive and names no org; Grace Semiconductor co-authors
   are affiliation only (Contract v7, D80b; sheng2012 rows carry the same empty fab with "0.13 um CMOS line, 248 nm DUV"). The
   wording names a node, so it is not a generic process (D536). A Grace-authored mapping for the benchmark, if wanted, belongs
   in `config/benchmark.yaml`.
4. AWG #4 geometry from Sec. 2. Recommendation: keep (noted on each row). The paper builds #4 "based on the comprehensive optimal
   design" (p.5, Fig. 3 caption), which Sec. 2 defines as the 1 um arrays plus the 20 um / 70 nm / 2.5 um bi-level tapers with
   450 nm bends at 5 um. Alternative: keep only the Fig. 3 caption parameters on #4 if the coordinator wants geometry only where
   the device is named.
5. nielson2005 split into `switch_fabric.mems` + `wdm.mrr` (D396). Recommendation: keep. The single MEMS element is
   `switch_fabric.mems` as barazani2023 / sharma2022 single MEMS switches and D594; the ring is the channel add-drop filter of
   the switch (D400), and the ring row carries a performance value (FSR) so it is a valid row (rule 9). The bridge-dependent
   drop IL / extinction stay on the switch row. Alternative: one switch row with the ring geometry in notes (D407 style), which
   loses the ring geometry from the wdm.mrr views.
6. nielson2005 fab org_mit and the two `author_estimate` rows. Recommendation: keep org_mit as borderline on both rows (D84b,
   Contract v7: thanks to MIT Microsystems Technology Laboratories technical staff "for support in fabrication", p.3; facility
   stays empty, D72); it applies to the ring row too since the ring is fabricated on the same chip (the cited ref. [6] process
   names no org). Keep ~1 uW at 100 kHz and FSR 12.5 nm as `author_estimate` (D82a / rule 4).
