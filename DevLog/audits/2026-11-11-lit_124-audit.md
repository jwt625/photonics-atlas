## Coordinator questions

1. Footprint stated once for a design family (asked for papadovasilakis2023; papadovasilakis2022 has the same construction). The BWIC
   footprint 36.3 x 3.8 um2 is printed for "the devices" (p.1) and for the BWIC ("its", p.11; one Table 3 row; "the device", p.12), while
   p.8 Table 1 gives SR-dependent LDC1 (0.91 / 1.08 / 1.37 L0) and yb (0.48 / 0.51 / 0.52 L0): the three bounding boxes differ, so the value can
   be exact for at most one design, and the paper does not say which. This is the D541 chen2019 case (value stated once for "the devices",
   rows deleted), not the lin2023 / govdeli2025 case (a bound or type statement that holds for each device). papadovasilakis2022 prints
   60 x 40 um2 once for "the wavelength-independent coupler" (p.1) and for splitting ratio "Any" (p.10 Table 2); the batch placed it on the
   0.50 row only, which D254 excludes. Recommendation: delete all four footprint rows and keep the values in component notes (patched).
   Alternative: keep the three papadovasilakis2023 rows with qualifier `approx` and a note on the Table 1 geometry spread (drop 3 of the 4
   delete_metrics and the footprint sentence of the BWIC notes); the papadovasilakis2022 single-row placement should go either way.
2. chen2021a facet-end width (asked). Recommendation: keep `tip_width_nm` 5000 (derived, unit conversion of the printed 5 um, D157). The
   `edge_taper` layout template uses `tip_width_nm` for the facet end and `width_nm` for the waveguide; merged up-taper rows use the same
   construction (li2026a tapered facet 8000 nm "top width at the end facet (up-taper from the waveguide)", liu2026d expanding tapers 5000 nm).
   `width_nm` would be read as the routing waveguide width by the drawing. No op.
3. chen2021a 4x4 per-port ILs (asked). Recommendation: confirm. The 6.6 / 6.85 / 6.54 / 6.62 dB values are per-port transmissions that include
   the ideal 6.02 dB quarter split; as `insertion_loss_db` they would read as a component loss, and they are not an imbalance (D401). The
   printed total (0.63 dB, `excess_loss_db`) and the spread (0.31 dB, `il_nonuniformity_db`) carry the information; the per-port values stay in
   notes until a `split_deviation_db` (or per-port transmission) parameter exists. No op.
4. Printed-value conflicts (asked). All three confirmed at their locators; recommendation in each case: keep the printed value, conflict in notes
   (D417).
   - papadovasilakis2023 split deviation: p.1 Abstract and p.12 conclusion print 0.6 % as the maximum deviation of the optimal device over
     100 nm; p.11 Table 3 prints 1.6 % for this work under its own definition (maximum non-uniformity of the best-performing device over the
     wavelength range, p.11); p.11 text uses 0.6 % for a different quantity, the maximum mean offset from the target (= Table 2 40:60,
     |0.394 - 0.40|). The audit also found p.2 "SD of only 0.6 %", which matches no Table 2 BWIC SD (0.8-1.3 %). No row carries a deviation
     value and none should: the best-performing device (SR, die) is not identified (D159). Notes rewritten to separate the three quantities.
   - papadovasilakis2022 IL at 1310 nm: printed "~0.16 dB" mean (p.2, p.10). Audit read of the Fig. 7(b) curve at 1310 nm: about 0.15 dB
     (+/- 0.01 dB). Fig. 7(b) is one extraction curve, the printed value a mean, so the difference is within reading accuracy and not a
     material conflict. Keep 0.16 dB `approx` (row unchanged; the existing note is adequate).
   - chen2021a Fig. 8(a) inset: more than a port swap. Tick-calibrated read of the embedded figure image: -6.54 (blue, Port4), -6.61 (red,
     Port2), -6.81 (black, Port1), -6.85 dB (green, legend repeats "Port2"). The printed 6.6 and 6.62 dB fall on one inset point (about 6.61),
     and the inset point at about 6.81 dB has no printed counterpart; the inset values sum to a total of about 0.68 dB instead of 0.63 dB, the
     spread is 0.31 dB either way. Keep the printed 0.63 dB (printed five times: p.1, p.2, p.7, p.9 Table 1, p.9 conclusion) and 0.31 dB; the
     alternative total is now in the m1 note and the component note.
