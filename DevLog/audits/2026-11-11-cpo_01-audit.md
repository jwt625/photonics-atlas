## Coordinator questions

1. COUPE 800 um support Si (batch-only `length_um` 800, design_target, p.3 Sec. IV.A). Value correct as printed
   ("800 um-thick support silicon layer over the EIC/PIC stack"). Recommendation: do not add it to the merged
   `cmp_ectc51687_2025_00015_coupe_lens_path`: `length_um` is "device length", and a class table would read 800 um as
   the length of a micro-lens; cov_tsmc already found no fitting micro_optics parameter, and the merged label and
   core_material state the 800 um. Registry candidate if wanted: a vertical path / substrate thickness parameter for
   micro_optics (e.g. `path_thickness_um`). Alternative: a merged-row fix adding it as `length_um` with the condition
   "support-Si thickness between GC and micro-lens".
2. levy2026 `process_name` (patched to empty). Recommendation: empty, because "Intel Fab11x" is a fab site that the
   registry already maps to org_intel, Contract v7 reserves process_name for a PDK / process / node / flow, and the
   ofc2026 Tu3C.2 rows with the same acknowledgement are empty. Alternative: keep the printed form "Intel Fab11x photonic
   IC (PIC)" (drop the process_name field from the component op; the notes op then needs its process sentence removed).
3. levy2026 centre wavelengths: one range row or 16 rows. Recommendation: one range row (kept), 16 values in condition,
   basis measured, n_samples 16. The array is one physical design (rule 9) and the merged precedent for printed
   per-laser lines is cmp_lit_nie2024_mp_mwl-m3 (range row). Per-lane rows exist too (cmp_lit_kanazawa2016_dml_array_tosa,
   cmp_lit_zhang2026a_dfb4_soa_array), where each lane has its own conditions; here all 16 share one condition.
